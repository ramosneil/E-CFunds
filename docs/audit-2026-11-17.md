# Full system check — 2026-11-17

Method: every server function run as each role with **dummy accounts** (5 accounts: SAS, 2 club treasurers, a 2nd
treasurer, a student; 2 dummy clubs; dummy students) inside one database transaction that was **rolled back** (nothing
kept, nothing real touched) — 79 + 6 checks. Plus a code sweep of every screen and the Android-only parts. The live
screen pass in Neil's Chrome could not run (Claude in Chrome was disconnected).

## Passed (works as intended)
Sign-up requests (no one can ask to be admin), SAS approvals (own account refused, one treasurer per org), student
list import, Add member (name required for new students), club import, record/undo payment with reason, receipts
(void kept, new number on re-pay), remind unpaid (1/day), remit/expense limits, receipt photo required, expense items,
release needs budget, budgets (treasurer can't approve own), SAS approve/reject (reason required), adjustments and
reversal, direct release limit, turnover blocked while a budget is open, announcements (SAS only), disable/enable
(not own), financial report = entity report totals, messages (can't post for another org or as someone else).
Students see only their own dues/receipts/notifications; no ledger, requests, budgets, messages, audit log or other
students; can't change their own role. Another club's treasurer can't see or touch this club's money. Signed-out
visitors get nothing.

## Recommendations (most important first) — see the chat report for details
1. Fingerprint / PIN unlock instead of a full sign-out every 5 minutes (keeps security, students stop retyping).
2. A second SAS admin account + 2FA for SAS (0 MFA factors today; one admin = one point of failure).
3. Cash-on-hand alerts: org holding cash too long → reminder to remit; SAS dashboard list.
4. QR code on receipts (scan = verify it's real).
5. Bulk "Record payment" for collecting in a room; offline queue for weak signal.
6. Automatic weekly backup to a SAS Google Drive (free plan has no point-in-time restore).
7. Treasurers look students up by ID instead of reading the whole student list (privacy, RA 10173).
8. Private GitHub repo; dedicated SAS Gmail as the email sender (personal Gmail, 500/day).
9. Play Store listing instead of APK side-loading (one-time $25).
