Technology Stack

This section presents the technology stack used to build E-CFunds, the student organization fund monitoring system of Occidental Mindoro State University – Mamburao Campus. It shows the tools that make up each part of the system, from the screens that students, treasurers and the SAS office use, to the database that keeps every peso on record. For each technology, it explains what it is, why the team chose it, and how it helps the system work.

Frontend

React19

React is a JavaScript library for building user interfaces from reusable components. We chose it because it is the most widely used front-end library, with many learning resources and ready-made tools. It helps E-CFunds by letting us build each screen (Dashboard, Members, Requests, Reports) once from shared parts, such as the fund card and the receipt, so the website and the Android app look and work the same.

TypeScript5.9

TypeScript is JavaScript with types. We chose it because money data must be exact, and types catch mistakes such as mixing up a peso amount with an ID before the code ever runs. It helps the system by checking every page against the real database structure, so a change in the database shows up as an error in the code instead of a bug for users.

Vite8

Vite is the build tool that runs the app during development and packages it for release. We chose it for its very fast start-up and instant reload while coding. It helps by producing small, optimized files, so E-CFunds loads quickly even on slow mobile data.

Tailwind CSS4

Tailwind CSS is a styling framework of small utility classes. We chose it because it keeps the design consistent and makes light and dark mode simple. It helps E-CFunds look the same on every screen size, from a phone to a desktop monitor, with one shared set of colors and spacing.

React Router and React Query8 · 5

React Router moves between pages, and React Query fetches and caches data from the database. We chose them because they are the standard pair for React apps. Together they keep pages fast, open the right page from a notification, and refresh the numbers the moment something changes.

Progressive Web App (vite-plugin-pwa, Workbox)

A Progressive Web App can be installed from the browser and keeps working with a weak connection. We chose it so students without the Android app still get an app-like experience. It helps by caching the app's files, showing an "offline" notice instead of a blank page, and updating the website automatically.

jsPDF and Excel libraries

jsPDF creates PDF files, and read-excel-file and write-excel-file read and write spreadsheets, all inside the browser. We chose them because reports can be made on the user's device with no extra server. They help E-CFunds produce receipts, the official Financial Report and summary reports as PDF, export ledgers to Excel or CSV, and import student and member lists from Excel.

Mobile

Capacitor8

Capacitor turns a web app into a real Android app that can use phone features. We chose it because it reuses the same React code, so we didn't have to build and maintain a second app. It helps E-CFunds reach the phone's notifications, the Back button, file sharing and downloads, while every feature stays the same as on the website.

Capgo updater

Capgo's updater downloads new versions of the app's code in the background. We chose it so users don't have to reinstall the APK for every fix. It helps by keeping every phone on the latest version automatically, which matters when a money rule or a screen changes.

Push and local notifications

These Capacitor plugins show alerts on the phone. We chose them because treasurers and students need to know right away when a payment is recorded or a request is decided. They help by delivering notifications even when the app is closed or the user is signed out.

Backend

Supabase

Supabase is an online backend that provides a PostgreSQL database, sign-in, file storage, live updates and server functions in one service. We chose it because it gives a complete, secure backend for free, without running our own server. It is the heart of E-CFunds: it stores every record and keeps all users' screens in sync.

PostgreSQL with Row Level Security

PostgreSQL is a reliable relational database; Row Level Security is its built-in rule system that decides which rows each user may see or change. We chose it because financial records need strict, provable rules. It helps E-CFunds keep every money rule inside the database: a treasurer can only touch their own organization, the ledger can never be edited or deleted, and every change is written to an audit log.

Supabase Auth

Supabase Auth handles accounts and sign-in. We chose it because it supports email and password, Google sign-in and email codes out of the box. It helps by letting students sign in with their Student ID and reset a forgotten password with a 6-digit code, while SAS approves each new account.

Supabase Storage

Storage keeps uploaded files. We chose it because it follows the same access rules as the database. It helps E-CFunds keep signed resolutions and liquidation files private, so only that organization's treasurer and SAS can open them.

Supabase Realtime

Realtime sends changes to open screens through a live connection. We chose it because fund monitoring must show current numbers. It helps the fund cards, lists and messages update within about two seconds of any transaction, without refreshing the page.

Edge Functions, pg_cron and pg_net

Edge Functions are small server programs written in TypeScript; pg_cron runs scheduled jobs and pg_net lets the database call those functions. We chose them to keep secret keys on the server and to automate tasks. They help E-CFunds send push notifications, answer questions in the assistant, sign students in by Student ID, and send weekly dues and daily reminders automatically.

Outside services

Firebase Cloud Messaging and Web Push

Firebase Cloud Messaging delivers notifications to Android phones, and Web Push delivers them to browsers. We chose them because they are the standard, free delivery channels on each platform. They help make sure every payment, request decision and reminder reaches the right person.

Google Gemini

Gemini is Google's AI model. We chose it for its free tier and good answers in plain language. It powers "Ask E-CFunds", the assistant that explains how to use the system and answers questions about the rules.

Gmail SMTP and Google OAuth

Gmail SMTP sends the system's emails, and Google OAuth provides "Continue with Google". We chose them because they are free, trusted and familiar to students. They help users confirm their email, reset passwords with a code, and sign in quickly with a Google account.

Hosting and DevOps

GitHub and GitHub Actions

GitHub stores the source code and its full history; GitHub Actions runs automatic jobs on every change. We chose them because they are free for our project and keep a record of every change. They help E-CFunds by building the signed Android APK automatically for each release and by keeping the database awake.

Vercel

Vercel hosts the website on a fast global network. We chose it because it deploys automatically from GitHub with free HTTPS. It helps by putting every update online within minutes, and by hosting the update package that the Android app downloads.

In summary, the team chose a stack that is free, secure and easy to maintain. One React and TypeScript codebase serves both the website and the Android app, while Supabase keeps all financial rules and records in one protected database. This combination helps E-CFunds deliver accurate, real-time and transparent monitoring of student organization funds.
